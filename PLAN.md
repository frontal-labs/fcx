Goal and scope ### 1.1 Goal An agent that is **very reliable on small, everyday coding tasks** on laptops with **8â€“16 GB RAM**, fully local, with **no daemon, no API key and no network port required**. It works in **TypeScript/JavaScript, Python, Go and Rust**, from the **terminal** and from **editors via the Agent Client Protocol (ACP)**. **Speed is a feature, not a polish item.** `fc` should feel instant: non-model commands return in tens of milliseconds, and a verified fix for a single diagnostic arrives in a few seconds on a warm process. Every design choice below that trades speed for something else says so. "Very reliable" here means three things. Edits compile and pass the relevant tests before the user sees them. The agent never references files, symbols or APIs that don't exist. It says so when it can't do a task, instead of pretending it did. ### 1.2 Core idea **The harness does the thinking; the model fills small, constrained slots.** - A **code graph plus hybrid search** decides what the model sees. - **Schemas generated from the graph** decide what the model is allowed to output. - **Deterministic checks** (language servers, type checkers, tests) decide whether an output is accepted. ### 1.3 In scope (v1) The 10 recipes in Â§9, CLI, ACP server, code graph, hybrid retrieval, six-layer hallucination defenses (Â§10), shared Frontal Code config (Â§5), local memory, eval harness, distillation/fine-tuning pipeline, escalation to Frontal Code providers. ### 1.4 Non-goals (v1) - Long-horizon or multi-file feature work. The router declines it (Â§9.1). - Open-ended agent loop with free-form tool calling. - Windows support. `ggml-node` supports it, but v1 targets macOS and Linux only; keep code portable, don't test it. - Session-file compatibility with Frontal Code's JSONL sessions. - Hosted/remote execution. --- ## 2. Every bug fix gets a regression test. 6. **Never escalate to a hosted model silently.** Escalation always needs explicit user approval, every time (Â§12.3). 7. **Stay within budgets.** Memory and latency budgets (Â§15) are CI-gated once M1 is reached. 8. **Match the tooling of `frontal-labs/ggml-node`** (Â§4.2) unless there's a recorded reason not to. --- ## 3. Keep the top 10 plus the seeds. 5. **Expand along the graph:** 1 hop from each hit (2 hops from the target) over `calls`, `references`, `imports`, `implements`, `tests`, and `co_changes` with weight â‰¥ 0.3. Expanded nodes score `parent_score Ã— 0.5^hops Ã— edge_weight`. 6. **Pack** blocks into `contextBudgetTokens`. Required blocks (target, error, sibling style example) go first, then the rest by score. On failure, the feedback (short, specific, one issue) goes into the next candidate's prompt. 1. **Constrain**: build schemas from the bundle's allow-lists: `z.enum(paths)`, `z.enum(symbolsInScope)`, `z.enum(importablePackages)`. Made-up paths can't even be expressed. Lists longer than 500 entries are trimmed by retrieval score, since huge enums slow grammar decoding (measure this). 2. **Ground**: parse the replacement code with tree-sitter and extract every referenced identifier and member access. Each must resolve to: a local definition in the edit, a symbol in scope (graph plus the file's imports), a dependency API (`deps` table), or a language builtin (`packages/defense/builtins/.json`). Unresolved identifiers fail with the feedback `Unknown identifier 'X'. Zero or several matches fail, with the nearest matching region in the feedback. 4. **Verify**: language-server overlay diagnostics first (no disk writes), then the verifier plan (Â§10.1). The UI shows the best candidate as "not verified", is never applied automatically, and offers escalation. Candidates run one at a time; stop at the first that passes every layer. **Log every layer outcome** to `logs/fc/defense.jsonl` as `{ task, recipe, layer, pass, reasonCode, ms }`.
